01 / 端到端交付流程

看主線，也看往返。

點擊流程卡，查看負責人、狀態與交付條件。箭頭代表交接，不代表所有工作必須串行。

本例 Story 需要設計；QA 規劃與設計、開發可並行。

交付主線並行／條件分支退回／繼續追蹤小螢幕可左右滑動流程圖 ↓
同一個 QA 交付包Bug 可並行，重疊等待不相加。
QA 測試投入與 RD 修復投入分開。

交接成立後，下一位尚未開始就保留待開始；真正開始才切處理中。圖上的前後順序是交付關係，QA 規劃與不受影響的測試仍可並行。

用文字順序看完整工作流 ＋
  1. PM／維運收單，建立功能或 OP 主卡。
  2. 跨組規劃範圍、驗收、日程；需要人時指標才另定投入估算。
  3. 需要設計才走 UIUX；QA 同時規劃與 Review 案例。
  4. RD 開發、自測與 Code Review，交付版本及環境；不完整就補齊。
  5. QA 確認可接手；真正開測時切處理中。
  6. 發現 Bug 就開在 QA 主單下，各自交 RD 修復；只讓受阻測試等待。
  7. RD 修好轉待 QA 複驗並指派 QA。QA 通過標已驗證，未過沿用同一張 Bug 退回。
  8. 必要測試完成、阻斷問題已處置，QA 交付報告，完成 QA 主單。
  9. 維運確認窗口、部署與 Prod 驗證。驗證未過，主卡保持未結案，依既有上線處置繼續追蹤修復及驗證。
  10. 必要交付與 Prod 驗證完成，需求／收單 Owner 確認主卡結案；試跑回顧資料品質與操作負擔。

02 / 圖上的工作，落在哪張卡？

主卡管交付，
QA 主單串起多張 Bug。

功能／OP 主卡需求、Owner、驗收標準與承諾日期
  • PM／UIUX／RD 職能工作卡 按實際需要建立
  • QA 測試規劃與案例 Review 按風險需要建立，可提前並行
  • QA 測試、複驗與報告主單Owner 保留 QA
    • BUG-01 RD 修復 → QA 複驗
    • BUG-02 RD 修復 → QA 複驗
    • 其他 Bug… 沿用關聯，獨立追蹤
  • 維運部署與 Prod 驗證卡

交棒有兩種，規則保持簡單。

跨職能

RD 完成自己的開發卡，確認下一張 QA 卡及接手人。QA 主單由 QA 維護。

同一張 Bug

RD 修好，改待 QA 複驗、指派 QA；通過才已驗證。歷史投入不因目前負責人改變而重分類。

03 / 每一步都通用的規則

正常交棒，例外才多記。

平常工作

待開始 → 處理中 → 完成

接卡先確認；開始才切狀態；交付時確認下一位。Bug 的完成點是 QA 標「已驗證」。

條件未到

等待 → 條件備妥後恢復

記原因與對象。等 QA 開始、QA 等修復、待部署分開辨識；等待不直接算任何人的投入。

核准插單

原卡暫停 → 回來繼續

關聯插單卡，記受影響工作並確認交期；插單處理完，回原卡切處理中，歷史持續累加。

日程與人時，各回答一個問題。

狀態及交接歷程解釋「為什麼這天才交付」；另行補登或計時回答「實際投入多少人時」。不把並行子卡加成整體交付時間，也不把 QA 父卡含 Bug 的彙總全算給 QA。
